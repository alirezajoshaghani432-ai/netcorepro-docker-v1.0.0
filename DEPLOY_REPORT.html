1 پیش‌نیازها و معماری پروژه

1.1 — معماری برنامه

NetCore Pro یک فروشگاه آنلاین B2B تجهیزات شبکه است که با:

  • Hono (وب‌فریم‌ورک سبک Edge-first) به‌عنوان Backend
  • SSR کامل با Template Literals (بدون React/Vue/Next — همه HTML از سرور می‌آید)
  • better-sqlite3 برای ذخیره‌سازی (یک فایل .db + WAL mode)
  • JWT + bcryptjs برای احراز هویت
  • Tailwind CSS به‌صورت از پیش build شده (نه نسخه CDN runtime)

1.2 — چرا این پروژه برای شرایط فیلترینگ ایده‌آل است

ویژگیتوضیح
تمام asset ها داخل پروژههیچ فایلی از CDN خارجی load نمی‌شود؛ Vazirmatn، Tailwind، FontAwesome، Axios، Chart.js همگی در public/static/ هستند.
دیتابیس فایلیSQLite — یک فایل، بدون نیاز به سرویس جداگانه
بدون call به API بین‌المللیMap، Maps API، Analytics و... استفاده نشده است
تک باینری nativeتنها بخش native پروژه better-sqlite3 است که در local_packages/ ارائه شده

2 آماده‌سازی سرور Ubuntu

2.1 — اتصال SSH

روی سیستم خود (یا از طریق کنسول وب VPS) به سرور متصل شوید:

ssh root@YOUR_SERVER_IP

2.2 — به‌روزرسانی پکیج‌های سیستم

قبل از هر کاری، apt را به آینه ایرانی تغییر دهید تا سرعت بالا برود و در شرایط فیلترینگ مشکل نخورید:

# بکاپ از sources.list فعلی
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak

# تغییر به آینه دانشگاه صنعتی شریف (هم‌چنان فعال‌ترین آینه ایرانی apt)
sudo sed -i 's|http://.*\.ubuntu\.com|http://mirror.iranserver.com|g' /etc/apt/sources.list

# آینه‌های دیگر در صورت شکست shariff:
# - http://mirror.faraso.org/ubuntu
# - http://archive.iut.ac.ir/ubuntu
# - http://mirror.0-1.cloud/ubuntu

sudo apt update
sudo apt -y upgrade

2.3 — نصب ابزارهای پایه

sudo apt -y install curl wget ca-certificates gnupg lsb-release \
                    ufw fail2ban htop nano vim git unzip rsync

2.4 — تنظیم فایروال (UFW)

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --force enable
sudo ufw status verbose
⚠️ هشدار: اگر از پورت SSH غیر استاندارد استفاده می‌کنید، حتماً قبل از فعال‌سازی UFW آن پورت را allow کنید وگرنه قفل می‌شوید.

2.5 — ساخت کاربر غیر root

sudo adduser deploy
sudo usermod -aG sudo deploy
sudo usermod -aG docker deploy   # این را بعد از نصب Docker اجرا کنید

3 نصب Docker از آینه ایرانی

docker.com از داخل ایران مسدود است. باید از آینه ایرانی Docker استفاده کنیم. آینه‌های فعال (در زمان نوشتن این راهنما):

سرویسآدرس Mirrorوضعیت
Liara Docker Mirrorhttps://docker.iranserver.com✅ فعال
ArvanCloudhttps://docker.arvancloud.ir✅ فعال
Hamdockerhttps://hub.hamdocker.ir✅ فعال
Iranserverhttps://docker.iranserver.com✅ فعال

3.1 — نصب Docker Engine

# نصب از مخزن apt اوبونتو (سریع‌تر و ساده‌تر از روش رسمی Docker.com)
sudo apt -y install docker.io docker-compose-v2

# استارت و فعال‌سازی سرویس
sudo systemctl enable --now docker

# بررسی نسخه
docker --version
docker compose version
💡 چرا apt به‌جای docker.com؟ چون apt mirror ایرانی فعال دارد ولی docker.com از داخل ایران در دسترس نیست. نسخه‌ی apt اوبونتو معمولاً ۱-۲ ماه عقب‌تر است که برای production کفایت می‌کند.

3.2 — تنظیم Docker Registry Mirror

این مهم‌ترین قدم است. باید Docker را وادار کنیم به‌جای registry-1.docker.io از آینه ایرانی image دانلود کند:

sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.iranserver.com",
    "https://docker.arvancloud.ir",
    "https://hub.hamdocker.ir"
  ],
  "insecure-registries": [],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  },
  "default-address-pools": [
    { "base": "172.30.0.0/16", "size": 24 }
  ]
}
EOF

sudo systemctl restart docker

# بررسی
docker info | grep -A 5 "Registry Mirrors"
⚠️ اگر هیچ آینه‌ای کار نکرد: آدرس آینه‌ها در طول زمان تغییر می‌کند. آخرین لیست را می‌توانید از کانال‌های زیر بگیرید: https://t.me/dockerhub_mirrors یا انجمن Liara.

3.3 — تست دانلود image

docker pull hello-world
docker run --rm hello-world

اگر این کار کرد، آینه Docker تنظیم شده است. اگر connection refused یا i/o timeout گرفتید، آینه‌ی فعالی پیدا کنید و در /etc/docker/daemon.json جایگزین کنید.

3.4 — Pre-pull کردن image پایه

برای صرفه‌جویی در زمان build، می‌توانید node:20-slim را از قبل دانلود کنید:

docker pull node:20-slim

5 آپلود پروژه روی سرور

چون GitHub در ایران مسدود است، چند گزینه دارید:

5.1 — روش 1: SCP/SFTP از ماشین لوکال

اگر فایل ZIP پروژه را در ماشین لوکال دارید (سیستم خودتان):

# روی ماشین لوکال (نه سرور!)

# سپس روی سرور:
ssh deploy@YOUR_SERVER_IP
mkdir -p /opt/netcorepro
cd /opt/netcorepro
unzip /home/deploy/netcorepro.zip
sudo chown -R $USER:$USER /opt/netcorepro

5.2 — روش 2: rsync (پایدارتر برای حجم زیاد)

rsync -avz --progress ./netcorepro/ deploy@YOUR_SERVER_IP:/opt/netcorepro/

5.3 — روش 3: Git از آینه (در صورت داشتن repo روی Gitlab Liara یا CodeCommit ایران)

cd /opt
sudo git clone https://gitlab.liara.ir/USERNAME/netcorepro.git
sudo chown -R $USER:$USER /opt/netcorepro

6 تحلیل Dockerfile

Dockerfile پروژه دو-مرحله‌ای (multi-stage) است:

6.1 — Stage 1: Builder

FROM node:20-slim AS builder

# 1. تنظیم Liara mirror برای npm
RUN npm config set registry https://package-mirror.liara.ir/repository/npm/

# 2. نصب better-sqlite3 از tarball محلی، بدون اجرای post-install
#    --ignore-scripts جلوی تلاش npm برای دانلود prebuilt از GitHub را می‌گیرد
COPY local_packages/better-sqlite3.tgz /tmp/
RUN npm install --ignore-scripts /tmp/better-sqlite3.tgz

# 3. جایگذاری دستی فایل باینری از پیش کامپایل‌شده
COPY local_packages/prebuilt/better_sqlite3.node \
     /app/node_modules/better-sqlite3/build/Release/

# 4. نصب سایر وابستگی‌ها (hono, bcryptjs, ...)
COPY package.json package-lock.json* ./
RUN npm install --omit=dev --ignore-scripts

6.2 — Stage 2: Runtime

این مرحله یک image سبک می‌سازد که فقط node_modules، dist/ و public/ از stage builder کپی می‌شود — بدون ابزارهای build، بدون tarball ها و بدون cache npm.

6.3 — چرا multi-stage مهم است؟

  • سایز نهایی کمتر: از ~500 MB به ~180 MB
  • امنیت: ابزارهای build (که سطح حمله گسترده‌تری دارند) در image نهایی نیستند
  • سرعت deploy: push image به registry سریع‌تر

6.4 — مقایسه با Dockerfile قبلی شما

مشکل قبلیراه‌حل جدید
npx tailwindcss داخل image — به lightningcss-native نیاز دارد که در ایران مسدود استTailwind از پیش روی سیستم توسعه build شده و public/static/css/tailwind.min.css در پروژه موجود است
نسخه‌ی single-stage — image بزرگmulti-stage — کاهش 60% در سایز
کاربر root داخل containerکاربر app بدون privilege
عدم وجود HEALTHCHECKhealthcheck داخلی هر 30 ثانیه
npm install بعد از COPY . . — کش نمی‌شوداول package.json کپی می‌شود، سپس کد منبع

8 عیب‌یابی build

❌ خطا: better_sqlite3.node: invalid ELF header

این یعنی باینری در local_packages/prebuilt/ با معماری/نسخه Node سرور سازگار نیست. راه‌حل: از Dockerfile جایگزین استفاده کنید که از سورس build می‌کند.

docker compose build --no-cache --build-arg DOCKERFILE=Dockerfile.build-from-source

یا در docker-compose.yml خط dockerfile: Dockerfile را به dockerfile: Dockerfile.build-from-source تغییر دهید.

❌ خطا: npm ERR! code ENOTFOUND یا getaddrinfo EAI_AGAIN

سرور به آینه Liara دسترسی ندارد. تست کنید:

curl -I https://package-mirror.liara.ir/repository/npm/

اگر این نیز timeout می‌دهد، DNS سرور را به DNS ایرانی تغییر دهید:

sudo nano /etc/resolv.conf
# اضافه کنید:
nameserver 178.22.122.100   # Shecan
nameserver 185.51.200.2     # Begzar
nameserver 8.8.8.8          # Google (در صورت قطع باشد)
❌ خطا: Error: Cannot find module 'hono' هنگام اجرا

node_modules در stage builder ساخته شده ولی به runtime منتقل نشده. بررسی کنید Dockerfile دارای این خط است:

COPY --from=builder /app/node_modules ./node_modules
❌ خطا: EACCES: permission denied, open '/app/data/netcorepro.db'

پوشه data/ روی host با کاربر root ایجاد شده ولی container با کاربر app اجرا می‌شود. رفع:

sudo chown -R 1000:1000 /opt/netcorepro/data /opt/netcorepro/uploads
❌ خطا: container restart می‌شود و در لاگ SIGTERM received

احتمالاً healthcheck شکست می‌خورد. تست manual:

docker exec -it netcorepro sh
node -e "fetch('http://localhost:3000/api/health').then(r=>r.json()).then(console.log)"

اگر healthcheck لازم نیست، در docker-compose.yml آن را موقتاً comment کنید.

❌ build بسیار کند است (بیش از 10 دقیقه)

پکیج‌ها از آینه Liara با کندی load می‌شوند. این موارد را در Dockerfile به Liara اضافه کنید:

RUN npm config set fetch-retries 5 && \
    npm config set fetch-retry-mintimeout 60000 && \
    npm config set fetch-timeout 600000

10 Nginx + HTTPS (Let's Encrypt با ZeroSSL برای ایران)

گواهی Let's Encrypt از داخل ایران ممکن نیست (سرور acme-v02 مسدود است). به‌جای آن از ZeroSSL یا Buypass استفاده کنید — هر دو با acme.sh سازگارند و در ایران در دسترس هستند.

10.1 — نصب Nginx

sudo apt -y install nginx
sudo systemctl enable --now nginx

10.2 — تنظیم Reverse Proxy

sudo nano /etc/nginx/sites-available/netcorepro

محتوای پیشنهادی:

server {
    listen 80;
    server_name yourdomain.ir www.yourdomain.ir;

    # اندازه آپلود (متناسب با MAX_BODY_SIZE_MB)
    client_max_body_size 10M;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        "upgrade";
        proxy_read_timeout 60s;
    }

    # cache برای static assets
    location /static/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_cache_valid 200 30d;
        add_header Cache-Control "public, max-age=2592000, immutable";
    }

    # gzip
    gzip on;
    gzip_types text/plain text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;
}
sudo ln -s /etc/nginx/sites-available/netcorepro /etc/nginx/sites-enabled/

10.3 — نصب acme.sh و گرفتن گواهی ZeroSSL

# صدور گواهی (روش webroot)

   --webroot /var/www/letsencrypt

برای webroot، خط زیر را موقتاً به Nginx اضافه کنید (در بلاک server):

location /.well-known/acme-challenge/ {
    root /var/www/letsencrypt;
}

11 پشتیبان‌گیری از دیتابیس

چون از SQLite استفاده می‌کنیم، پشتیبان‌گیری به‌سادگی کپی فایل است.

11.1 — اسکریپت backup دستی

فایل /opt/netcorepro/backup.sh بسازید:

#!/bin/bash
set -e

BACKUP_DIR="/opt/backups/netcorepro"
DATE=$(date +%Y-%m-%d_%H-%M-%S)
mkdir -p "$BACKUP_DIR"

# استفاده از SQLite .backup command (آن‌لاین، بدون نیاز به stop سرویس)
docker exec netcorepro sh -c \
  "sqlite3 /app/data/netcorepro.db '.backup /app/data/backup-$DATE.db'" 2>/dev/null || \
  docker cp netcorepro:/app/data/netcorepro.db "$BACKUP_DIR/netcorepro-$DATE.db"

# فشرده‌سازی
gzip "$BACKUP_DIR/netcorepro-$DATE.db" 2>/dev/null || true

# حذف بکاپ‌های قدیمی‌تر از 14 روز
find "$BACKUP_DIR" -name "*.db*" -mtime +14 -delete

# لاگ
echo "[$DATE] backup completed: $(ls -lh $BACKUP_DIR/netcorepro-$DATE.db*)" \
  >> "$BACKUP_DIR/backup.log"
chmod +x /opt/netcorepro/backup.sh

# تست
/opt/netcorepro/backup.sh
ls -la /opt/backups/netcorepro/

11.2 — Cron برای پشتیبان‌گیری روزانه

sudo crontab -e

# خط زیر را اضافه کنید (هر روز ساعت 3 بامداد):
0 3 * * * /opt/netcorepro/backup.sh >/dev/null 2>&1

11.3 — بازگردانی از بکاپ

# متوقف کردن container

# Restore فایل

gunzip -c netcorepro-2026-05-26_03-00-00.db.gz > /opt/netcorepro/data/netcorepro.db

# دوباره راه‌اندازی
